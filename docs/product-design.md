# 课程表 · 产品设计文档

> 状态：草稿（待确认）
> 日期：2026-09-17
> 说明：本文档界定 MVP 的产品方向与功能范围，技术实现方案另见后续文档。

## 1. 产品定位

一个**自己用的**课程表网页应用，装在安卓手机上像 App 一样使用。

解决的核心问题只有三个：

1. 上课前能快速确认「今天上什么、在哪上」
2. 课表能准确表达国内高校的排课规则（单双周、起止周次）
3. 录一次课不用重复劳动

## 2. 目标与非目标

**目标**

- 单机可用，无需注册、无需联网
- 手机上打开即用，可添加到主屏，全屏体验接近原生 App
- 课表规则的表达准确，宁可录入麻烦一点也不允许展示出错

**非目标（本版本明确不做）**

- 账号体系、云端同步、跨设备
- 后台系统通知、推送服务
- 与学校教务系统直接对接
- 社交功能

## 3. 目标用户

仅作者本人使用，单个用户、单台设备、单个学期。

因此所有涉及多用户、多端的复杂度都可以省略。

## 4. 使用场景

| 场景 | 触发时机 | 期望结果 |
| --- | --- | --- |
| 课前确认 | 走进教学楼、坐下前 | 一眼看到今日课程与教室 |
| 查某门课 | 想知道某课在哪、老师是谁 | 点格子看到完整详情 |
| 查未来 | 想知道这周或下周的安排 | 切换周次查看完整课表 |
| 录入课表 | 开学初、选课变动后 | 一次录完，自动展开到所有周次 |
| 检查冲突 | 录入时 | 时间重叠立刻提示 |

## 5. MVP 功能范围（P0）

### 5.1 周课表视图

课表主界面，整个产品的核心。

- **布局**：横向为周一至周日，纵向为节次/时间
- **格子内容**：课程名 + 教室（格子空间有限，其余信息进详情）
- **周次切换**：可切换查看不同周的课表，默认显示当前周
- **点击格子**：查看详情——课程名、老师、教室、周次范围、节次

**必须表达的排课规则**（这是国内课表最容易出错的地方）：

- **起止周次**：一门课可能只上第 1~8 周，或第 10~16 周
- **单双周**：每周 / 仅单周 / 仅双周
- **组合情形**：如「第 1~16 周，单周」，实际开课周为 1、3、5……15

判定某个日期是否显示某门课的逻辑：

```
该日期所在周的周次 = 该周周一与学期第 1 周周一的日期差 / 7 + 1
显示条件 = 周次在 [起周, 止周] 区间内 且 满足单双周条件
```

### 5.2 课程的手动增删改

- **一次录入生成多条**：选择星期几、节次、周次范围、单双周、教室、老师后，系统自动展开到所有符合条件的周次，避免逐周重复录入
- **冲突检测**：新录入或修改课程时，若与已有课程在时间上重叠，立即提示冲突及冲突对象
- **编辑与删除**：修改课程信息或整门课移除

冲突检测的口径：两门课「星期几相同 + 节次有交集 + 周次区间有交集 + 单双周条件同时满足」即视为冲突。例如单周课与双周课在同一时间不算冲突。

### 5.3 今天 / 下一节课

首页的即时信息区，解决最高频的场景。

- 有课时显示：「今天第 3-4 节 高等数学 @三教 302」
- 无课时显示：「今天没课」
- **当前正在上的课高亮**，并显示剩余分钟数
- 无课时给出「下一门课」的提示，方便提前准备

### 5.4 数据持久化

- 数据保存在浏览器本地，不依赖网络
- 无账号、无登录、无同步

需要注意的是本地存储存在被浏览器清理的可能，因此需要提供**手动导出/导入数据**的兜底手段（可作为 P1）。

## 6. 后续规划（P1）

按优先级排序。

### 6.1 学期设置（建议随 MVP 一起做）

- 设置第 1 周的起始日期
- 自动计算当前是第几周

**这不属于锦上添花**：没有学期起始日期，周次无法计算，「起止周次 + 单双周」的 P0 逻辑就无法落地。因此建议它随 MVP 一起交付。

### 6.2 导入课表

- 粘贴学校教务系统的课表文本，解析为课程数据

这是痛感最强的功能，也是留存收益最高的一个。各校文本格式差异较大，需要先收集实际样本再定解析方案。

### 6.3 多套课表 / 切换学期

- 支持多份课表并存，例如主修与选修分开
- 支持切换学期，保留历史学期的课表

### 6.4 数据导出/导入

- 导出一份文件用于备份或换设备
- 作为本地存储被清理时的兜底

## 7. 术语与数据约定

统一定义，避免后续实现产生歧义。

| 术语 | 含义 |
| --- | --- |
| 学期 | 一个连续的排课周期，由起始日期与总周数界定 |
| 周次 | 从 1 开始计数，第 1 周由学期起始日期决定 |
| 节次 | 一天内的上课时段编号，如第 3-4 节为一个连续时段 |
| 单双周 | 以周次的奇偶性区分，单周指奇数周次 |
| 课程 | 一门课的名称、老师等固定信息 |
| 上课时段 | 课程在「星期几 + 节次 + 周次范围 + 单双周」上的具体安排 |
| 冲突 | 同一时间存在两门及以上课程 |

一门课程可以对应多个上课时段（例如同一门课一周上两次，分别在周二和周四）。

## 8. 待确认事项

以下问题会影响实现，需要先拍板：

1. **节次时间表**：使用一套内置的默认节次时间（如第 1 节 8:00-8:45），还是允许自行配置？若用默认值，需要提供本校的实际时间段。
2. **学期起始日**：第 1 周的周一具体是哪一天？
3. **总周数**：一个学期按多少周计算（常见为 16、18 或 20 周）？
4. **P1 取舍**：确认「学期设置」随 MVP 一起交付，导入与多套课表放到第二批。
